# B/S 模式访问安全 · 改造记录

**日期**：2026-09-30
**起因**：用户指出「这是本地软件，只有用户授权外网访问时才能提供访问，否则存在安全问题」

## 问题（改造前的真实状态）

1. `--addr` 可任意填 `0.0.0.0:8788`，**没有任何拦阻**——一条命令就把整个书架挂到局域网。
2. HTTP 服务**完全没有鉴权**：能连上端口的人可以读全部书目与封面、改书架/标签/评分、改设置，
   还能调 `/api/open` 让系统默认程序打开库内文件。
3. 无 Host 头校验，存在 DNS rebinding 风险。
4. 顺带发现：**未添加库时 `/api/items` 直接空指针 panic**（远程可触发的服务停摆）。

## 改造后的五条硬约束

| 约束 | 行为 |
|---|---|
| 默认只绑回环 | `127.0.0.1`；`0.0.0.0` / 空主机 / 局域网 IP 一律按「对外暴露」处理 |
| 对外需显式授权 | 非回环地址必须带 `--allow-remote`，否则拒绝启动；启动后打印「无 TLS、同网段可访问」的风险提示 |
| 一律要求令牌 | 每次启动生成 128 位随机令牌，打印在访问地址里；首次进入转存 `HttpOnly` + `SameSite=Strict` Cookie，地址栏立刻去掉令牌；无令牌的静态资源/缩略图/API 全部 401 |
| Host 头校验 | 只认 `127.0.0.1` / `localhost` / `::1`（授权对外时追加绑定地址）→ 阻断 DNS rebinding |
| 跨站防护 | 不发任何 `Access-Control-*` 头；`SameSite=Strict` 阻断 CSRF；`nosniff` + `no-referrer` |

桌面壳的「在浏览器中打开」改为：内部生成令牌 → 只绑回环 → 打开带令牌的地址，用户无需手抄令牌。

## 验证（实测）

| 场景 | 结果 |
|---|---|
| `--serve --addr 0.0.0.0:8891`（未授权） | 拒绝启动：「拒绝绑定 0.0.0.0:8891：这不是本机地址…请显式加 --allow-remote」 |
| `--serve --addr 192.168.2.50:8891`（未授权） | 拒绝启动 |
| `--serve --addr :8891`（空主机=所有网卡） | 拒绝启动 |
| `--serve --addr 127.0.0.1:8891` | 启动并打印 `http://127.0.0.1:8891/?token=<hex>` |
| 裸 socket `GET /api/items`（无令牌） | 401 |
| 裸 socket `GET /?token=<正确>` | 302 + `Set-Cookie: bookrest_token=…; HttpOnly; SameSite=Strict` |
| 裸 socket `GET /api/items?token=<错误>` | 401 |
| `Host: evil.com` + 正确令牌 | 403 |
| `Origin: https://evil.com` | 响应无任何 `Access-Control-*` 头 |
| 未添加库时 7 个查询接口 | 全部 200（修复前 panic） |

新增用例：`internal/server` 6 个（拒绝未授权绑定、令牌全路径校验、Host 守卫、无 CORS 头、令牌随机性、无库不崩）。

## 已知边界（诚实说明）

- 服务**没有 TLS**：授权对外时，同网段拿到那条 URL 的设备即可访问；仅在可信网络使用，用完请关闭。
- 令牌走 URL 查询串首次进入，理论上会出现在浏览器历史/书签里——已在服务端立刻 302 去掉地址栏令牌，但浏览器历史里可能仍留有那条地址。
- 令牌是「持有即通行」，没有用户体系与权限分级（本地单用户软件的合理取舍）。
