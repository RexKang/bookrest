## 1. 架构总览

### 1.1 中心思想：两本账

架构只有一个中心思想：**把「事实」和「意图」彻底分开**。

- **事实账**（可重建）：文件名、大小、指纹、内嵌元数据、页数 —— 全部可以从文件系统重新推导，坏了就重扫
- **意图账**（不可重建）：书架、顺序、标签、自定义标题、评分 —— 只存在于用户的头脑与我们的文件里，丢了就没了

其余设计都是这条的推论：镜像为主（事实与意图都放本机运行时）、库内快照（意图必须可携带）、指纹身份（文件搬家不换身份）、离线只读（事实可重建所以离线只读也够用）、冲突不静默（意图不能被覆盖）。

### 1.2 分层

```
        ┌───────────────── UI 层（Web / TS）─────────────────┐
        │  书架视图（架层/书脊）· 封面墙 · 详情页 · 体检 · 设置  │
        └────────▲──────────────────────────────┬───────────┘
             查询 │                          意图 │
        ┌────────┴──────────────────────────────▼───────────┐
        │  应用层（Go）：查询服务 · 摆放编辑 · 设置 · 事件推送  │
        └────────▲──────────────────────────────┬───────────┘
                 │                              │
   ┌─────────────┴────────────┐     ┌───────────▼────────────┐
   │ 领域层（纯逻辑，无 IO）     │     │ 后台任务（worker pool）  │
   │ 指纹身份 · 元数据合并 ·    │     │ 扫描 · 缩略图 · 快照同步 │
   │ 系列卷号 · 体检规则        │     │ 可取消 · 可断点续扫      │
   └─────────────▲────────────┘     └───────────┬────────────┘
                 │                              │
        ┌────────┴──────────────────────────────▼───────────┐
        │  基础设施层（Go）：解析器(zip/epub/pdf) · 镜像存储    │
        │  · 库内快照 · 系统集成（默认程序打开/在文件夹中显示）  │
        └───────────────────────────────────────────────────┘
```

| 层 | 职责 | 硬约束 |
|---|---|---|
| UI | 渲染书架/封面墙、拖拽、详情、体检展示 | 虚拟滚动；书脊用 CSS；不直接访问文件系统 |
| 应用层 | 查询（过滤/排序/分页）、摆放编辑、设置、事件推送 | 唯一对外接口面（IPC 契约）；外壳可替换而此层不动 |
| 领域层 | 指纹与身份、元数据合并与覆盖规则、系列/卷号模型、体检规则 | 纯逻辑、无 IO、可单测 |
| 后台任务 | 扫描、缩略图生成、快照同步 | 扫描池 2–4 线程；缩略图独立 CPU 池；全部可取消 |
| 基础设施 | 文件解析、镜像读写、库内快照、系统集成 | 源文件只读；自数据原子写 |

### 1.3 进程与线程模型

- **单进程**：Go 主进程 + 一个 WebView（或浏览器页面，取决于外壳选择）
- **goroutine 池**：
  - 扫描池：默认 `min(4, NumCPU)`，网络存储路径自动降到 2
  - 缩略图池：`min(4, NumCPU/2)`（CPU 密集）
  - 同步队列：单协程串行（保证写入顺序）
- **取消**：所有长任务带 `context.Context`，界面上的取消按钮触发 cancel，游标落盘后进入 Cancelled 状态

## 3. 数据模型

### 3.1 事实索引 `index.jsonl`（本机镜像，可重建）

每行一条 JSON 记录：

```json
{
  "v": 1,
  "id": "5f2a9c1b7e30d4a8",
  "fp": { "size": 104857600, "head": "b2f1c3...", "mtime": 1759100000 },
  "rel": "Series A/vol01.cbz",
  "ext": "cbz",
  "pages": 192,
  "meta": { "title": "卷一", "series": "Series A", "number": "1",
            "author": "某人", "artist": "某人", "year": 2020, "src": "comicinfo" },
  "art": { "thumb": true, "spine": true, "failed": false },
  "seen": { "first": 1759100000, "last": 1759100000 },
  "flags": { "missing": false, "id_unstable": false, "dup_of": null }
}
```

| 字段 | 说明 | 约束 |
|---|---|---|
| `id` | 身份（见 §5.3） | 库内唯一 |
| `fp.head` | 首 64KB 的 blake2b-128 | 用于身份与变更检测 |
| `rel` | 相对库根的路径（统一 `/` 分隔） | 不含库根 |
| `pages` | 页数（zip 内图片项数） | 无法判定时为 null |
| `meta.src` | 元数据来源：`comicinfo` / `opf` / `xmp` / `filename` | 决定覆盖优先级 |
| `art.*` | 缩略图/书脊是否已生成 | 缓存文件缺失时置 false |
| `flags.missing` | 本轮扫描未见到的记录 | 保留 7 天后可清理（可配） |

**写入策略**：整文件重写 + 原子替换（变更不频繁，2 万条约 10–20MB，SSD 写入 < 100ms）。

### 3.2 意图 `shelf.json`（唯一不可重建的资产）

```json
{
  "v": 1,
  "rev": 42,
  "device": "desk-win",
  "updated_at": "2026-09-29T22:10:00+08:00",
  "shelves": [
    { "id": "s_01", "name": "必读", "order": ["5f2a9c1b7e30d4a8", "91bc77aa02f1c3de"] },
    { "id": "s_02", "name": "画集", "smart": { "rule": "tag:画集" } }
  ],
  "overrides": {
    "5f2a9c1b7e30d4a8": { "title": "自定名", "tags": ["画集"], "rating": 5 }
  },
  "ui": { "active_shelf": "s_01", "spine_style": "wood" }
}
```

| 字段 | 说明 |
|---|---|
| `rev` | 单调递增；每次写入 +1；用于冲突检测 |
| `device` | 最后写入者的设备标识（用于冲突提示） |
| `shelves[].order` | 架层顺序（v1 的「摆放」即顺序） |
| `shelves[].smart.rule` | 智能书架规则（P1），如 `tag:画集`、`series:Series A` |
| `overrides` | 用户覆盖项；删除用墓碑 `{ "deleted": true }`，避免重扫后「复活」 |
| `ui` | 界面状态（激活书架、书脊样式），随意图一起走 |

### 4.1 领域与基础设施接口（Go）

```go
type Identity struct { ID string; Size int64; HeadHash string }
```

## 5. 关键流程

### 5.1 启动时序

1. 读 `config.json` → 读本机 `shelf.json` + `index.jsonl` → 建内存模型（2 万本目标 < 300ms）
2. 界面立即渲染（使用 `ui.active_shelf`），此时已有书架全貌
3. 并发探测库可达性（`stat` 库根，超时 2s）→ 不可达则发 `lib.offline` 并切只读
4. 可达则后台启动增量扫描 → `scan.diff` 事件驱动界面增量更新
5. 可见区缩略图按需请求（懒生成），滚动到才生成

**关键点**：任何一步都不等待扫描完成，界面不出现「加载中」白屏。

### 5.2 增量扫描状态机

```
Idle → Probe(递归检查目录 mtime) → Diff(变化目录内逐文件 stat 比对)
     → Hash(新增/变更文件：首 64KB + size) → Parse(读元数据) → Commit(写 index + scan_state)
     → [Thumb 分离，懒生成] → Done
任意阶段 → Cancelled（游标落盘，可续扫）
```

**剪枝算法（性能关键）**：只 `stat` 目录、不 `stat` 文件。

- 从库根开始递归：目录 mtime 与 `scan_state.dirs` 一致 → **整棵子树跳过**
- 目录 mtime 变了 → 进入该目录，对直接子文件做 `(size, mtime)` 比对，只有变化的才重算指纹
- 复杂度从 O(文件数) 降到 O(目录数)：2 万本 / 平均 20 本每目录 ≈ 1000 个目录 → 1000 次 `stat` 而非 2 万次

**两个实测驱动的修正**（实现期发现，已回写）：

1. **目录 mtime 会延迟落定**：Windows/NTFS 上写入文件后，父目录 mtime 可能在本轮扫描开始后才被系统补写（实测延迟数毫秒）。因此只有「早于本轮扫描开始」的 mtime 才写进状态表；在扫描开始后仍变动的目录记为 0（不可信），下一轮必然重查。结果是：某目录变更后的**第一次重扫只做 stat（不哈希、不解析）**，第二次起即可整棵剪枝 —— 代价很小且绝不永久漏检。
2. **条目数作为第二道判据**：剪枝要求「mtime 一致」且「直接子项数量一致」。增删/改名必然改变子项数量，即使 mtime 尚未落定也能识别，避免「刚加完文件立刻扫描却看不到」。

**已知盲区**：文件原地覆盖写（内容变了但目录 mtime 与子项数量都不变）无法被剪枝识别。兜底：FR-1.5 周期全量校验（默认每 7 天或每 20 次启动）+ 手动「强制重扫」。

### 5.3 身份与指纹

- 身份：`id = hex(hash(file_head_64KB ‖ uint64(size)))[:16]`；实现用标准库 `crypto/sha256` 截断 128 位（避免引入 `x/crypto` 依赖，语义等价）
- **移动/重命名认领**：`id` 命中但 `rel` 变化 → 更新 `rel`，保留摆放与覆盖，发 `scan.diff.moved`
- **重复判定**：两个文件同 `id` → 全文件 blake2b 二次确认；仍相同 = 真重复（进体检 FR-5.2）
- **碰撞处理**（罕见）：同 `id` 但内容不同 → 降级身份 `id = hex(blake2b-128(rel ‖ size ‖ mtime))[:16]`，置 `flags.id_unstable = true`
- **缺失**：本轮未出现的 `id` → `flags.missing = true`（不立即删除，保留摆放 7 天，可配）

### 5.4 缩略图与书脊懒生成

```
请求(id, size) → 内存 LRU（热） → 磁盘缓存 cache/thumbs|spines/<id>.webp
              → 未命中：入队（按 id 去重）→ 生成 → 原子写 → thumb.ready
```

- 封面：打开 zip 取首个图片项（按名称排序）→ 解码 → `thumbnail(320×480)` → webp q75（实测 22.5ms/本）
- 书脊：**从已生成的缩略图派生**（不重新解码原图）→ 裁左侧 10% 宽条 → 缩放到 48×300 → webp
- 无封面/损坏 → 占位图（按标题 hash 取稳定色块）+ `thumb.failed` + 进体检 FR-5.3
- 并发：`min(4, NumCPU/2)`；同一 `id` 的并发请求合并为一次生成

### 5.5 意图写入与库内同步

```
拖拽 → 内存模型更新（乐观，界面立即生效）
     → 原子写本机 shelf.json（rev+1）
     → 去抖 5s（可配）→ 同步队列（单协程串行）
         读库内 shelf.json 的 rev_remote
         ├─ rev_remote ≤ rev_local → 原子写库内 → sync.state(ok)
         └─ rev_remote >  rev_local → 备份库内为 shelf.conflict-<ts>.json
                                      → 发 conflict.detected → 本机不变
退出前强制 flush；同步失败（离线/只读/纯本机模式）→ 保留 dirty 标记，下次启动重试
```

### 5.6 离线降级

- 探测：`stat` 库根，超时 2s；连续 2 次失败判定离线
- 离线态：只读（书架、封面、摆放照常）、顶部横幅提示「目录不存在：<root>」、禁用拖拽与库内写入
- 恢复：探测成功后自动重试同步并退出离线态

## 6. 存储与原子性

### 6.1 目录布局

```
本机镜像  %APPDATA%\bookrest\
  config.json               配置
  mirror\index.jsonl        事实账（可删可重建）
  mirror\shelf.json         意图账（资产）
  mirror\scan_state.json    扫描游标与目录 mtime 表
  backups\shelf.<rev>.json  滚动备份
  cache\thumbs\<id>.webp    缩略图（可删）
  cache\spines\<id>.spine.webp
  logs\

库内      <库根>\.bookrest\
  shelf.json                意图快照（权威、可携带、可 git / 网盘同步）
  index.jsonl               事实快照（默认同步，体积小）
  （缩略图默认不写库内）
```

### 6.2 原子性与恢复

- **原子写**：写 `*.tmp` → `fsync` → `rename`（同目录同卷，Windows 上 `os.Rename` 覆盖语义需先 `os.Remove` 或使用 `MoveFileEx` 语义封装）
- **备份**：`backups/shelf.<rev>.json`，保留最近 20 份 + 每日 1 份保留 30 天
- **损坏恢复**：`shelf.json` 解析失败 → 自动回退最近可用备份并提示；`index.jsonl` 解析失败 → 丢弃并触发重扫（事实可重建，不打扰用户）

## 7. 性能设计

### 7.1 实测基准（本机 Windows 11 / NTFS，合成库；Python 单线程口径，Go 实现通常更快）

| 环节 | 首次访问 | 热态 | 说明 |
|---|---|---|---|
| 目录遍历 + stat | 0.02ms/本 | 0.02ms/本 | — |
| zip 打开 + 读元数据 | 6–8ms/本 | 0.08–0.17ms/本 | 首次成本来自 OS/杀软扫描，非解析本身 |
| 抽封面字节 | 0.13ms/本 | 0.13ms/本 | — |
| 弱指纹（首 64KB） | 0.13ms/本 | 0.13ms/本 | 增量扫描基石 |
| 页数统计 | 0.06ms/本 | 0.06ms/本 | 厚度映射用 |
| 封面 → 192×288 JPEG q70 | 待测（参考：Python 解码+缩放+编码 22.5ms/本） | — | 纯 CPU，缩略图池并行 |
| 缩略图产物体积 | 封面 16.6KB/本 + 书脊 3.0KB/本 = 19.6KB/本（合成噪声图=最坏情况） | — | 2 万本全量浏览 ≈ 390MB；真实封面约小 30%，且懒生成 |

### 7.2 外推

| 库规模 | 全量冷扫（元数据 + 缩略图，单线程 / 4 线程） | 增量（热） | 缓存体积 |
|---|---|---|---|
| 1,000 本 | 30s / ~9s | < 1s | 5MB |
| 5,000 本 | 2.5min / ~43s | ≤ 1s | 25MB |
| 20,000 本 | 10min / ~3min | ≤ 3s | 100MB |

### 7.3 内存预算（2 万本）

| 项 | 估算 |
|---|---|
| 事实记录（20k × ~400B） | ~8MB |
| 内存索引与字符串驻留 | ~30–60MB |
| UI（WebView + DOM ≤ 200 节点） | ~80–120MB |
| 合计 | **≤ 300MB**（PRD 指标） |

### 7.4 其它

- 虚拟滚动：只渲染可见区 + 缓冲行，DOM 节点上限 ~200
- 事件节流：`scan.progress` 每 200ms 聚合一次，避免事件风暴
- 查询：内存过滤（2 万本 ≤ 200ms），索引内建倒排（标签/系列 → id 列表）
- 测试数据预算：全部测试数据写入 **≤ 1GB**（生成器内置硬上限，超限即失败）；分级策略见测试方案文档 —— 日常回归 2,000 本，2 万本仅里程碑发版前跑一次

## 8. 安全与隐私

| 项 | 措施 |
|---|---|
| 源文件只读 | 一律只读句柄打开；v1 不提供任何写源文件能力 |
| 不越界扫描 | 不跟随指向库外的符号链接；跳过系统目录与隐藏的系统文件夹 |
| 不写源目录 | 库内写入仅限 `<库根>/.bookrest/`，且可整体关闭（FR-6.7） |
| 路径安全 | 打开文件交给系统 API（不经 shell 拼接）；文件名只作展示，不执行 |
| 日志脱敏 | 只记相对路径，不记含用户名的绝对路径 |
| 网络 | **默认零网络请求**；无遥测；在线信息补全只在用户点「搜索书籍信息」时发生（见 §8.2） |
| 指纹用途 | 仅用于本机身份判定，不上传、不用于内容识别 |

### 8.1 B/S 模式的访问安全（r2 新增）

拾书是本地软件。桌面窗口（C/S）天然只有本机可及；B/S 模式属于「把本机能力挂到 TCP 端口上」，
必须默认不可达、且必须由用户显式授权才能对外，因此定下五条硬约束：

| 约束 | 实现 |
|---|---|
| 默认只绑回环 | 监听地址默认 `127.0.0.1`；`0.0.0.0`、空主机名、局域网 IP 一律视为「对外暴露」 |
| 对外需显式授权 | 绑定非回环地址必须带 `--allow-remote`，否则**拒绝启动**并说明后果；启动后打印风险提示（无 TLS、同网段可访问） |
| 一律要求令牌 | 每次启动生成 128 位随机令牌；访问地址形如 `http://127.0.0.1:8788/?token=<hex>`；首次进入转存 `HttpOnly` + `SameSite=Strict` Cookie，地址栏立即去掉令牌；未带令牌的请求（含静态资源、缩略图、API）一律 401 |
| Host 头校验 | 只接受 `127.0.0.1` / `localhost` / `::1`（授权对外时追加绑定地址），阻断 DNS rebinding |
| 跨站防护 | 不发送任何 `Access-Control-*` 头；`SameSite=Strict` 阻断 CSRF；附带 `X-Content-Type-Options: nosniff` 与 `Referrer-Policy: no-referrer` |

### 8.2 在线信息补全（r3 新增）

封面与书目信息支持**按需联网**获取，但严格限定在用户主动动作上：

| 约束 | 实现 |
|---|---|
| 触发 | 只在书籍详情里点「搜索书籍信息」时联网；扫描、启动、浏览全程不联网 |
| 发送内容 | 只发送书名/系列/卷号/作者这类书目字段；**不发送路径、文件内容、指纹** |
| 目标域名 | 固定白名单：`googleapis.com`、`books.google.com`、`openlibrary.org`、`covers.openlibrary.org`、`api.bgm.tv`、`lain.bgm.tv`；不接受任意 URL（同时防 SSRF） |
| 传输 | 一律 https；封面由本机下载进缓存，**不热链**站外图片 |
| 代理 | 默认跟随 Windows 系统代理设置（读 `Internet Settings` 注册表）；可设「直连」或自定义代理 |
| 结果处置 | 候选由用户挑选（用这条 / 只用封面 / 忽略）；写入的是本机意图（override），不动源文件 |
| 缓存 | 封面属派生数据，存镜像目录 `covers/`，可整体删除；记录来源与查询串便于追溯 |
| 失败处理 | 单个源失败不影响其它源；全部失败只报错不重试轰炸 |

手动通路同样保留：粘贴剪贴板图片、选择本地图片文件、直接编辑字段。

补充约定：

- 令牌不落盘（只存在于进程内存与用户手里那条 URL）。
- 「在浏览器中打开」由外壳内部生成令牌并只绑回环，用户无需手抄令牌。
- 无库状态下任何查询接口都必须正常返回空结果，不允许 panic——B/S 模式下崩溃等同于远程可触发的服务停摆。

## 11. 技术选型与决策记录

| 决策 | 结论（r1 冻结） | 理由 | 替换成本 |
|---|---|---|---|
| 外壳 | **Wails v2**（Go 后端 + Web 前端） | 定位要求轻量（Electron 安装 50–150MB+，与「比 Calibre 轻」冲突）；与作者技能栈（Go + TS）咬合；v1 仅 Windows，系统 WebView 差异风险可忽略；Wails v3 仍是 beta，暂不采用 | 低：`transport/` 一层抽象，内核不动 |
| 索引存储 | **JSONL + 内存索引** | 零依赖、可读、符合零锁定；2 万条约 10–20MB，启动解析几百毫秒；写入用整文件原子替换 | 中：`Index` 接口隔离，可换 SQLite |
| UI 技术 | **vanilla TS + 少量轻量库** | 书脊 + 虚拟滚动不需要框架全家桶；依赖越少越稳 | 中 |
| CBR（rar） | v1 不支持 | 需外部解压库（unrar/7z）或 libarchive；v1 明确写进非目标 | 低（后加解析器即可） |
| 摆放模型 | 架层 + 顺序 | 自由 2D 画布留 v2（响应式重排与持久化复杂度高） | 中 |

> 技术结论冻结后，本文档相关条目转为 ADR 落 `docs/decisions/`。
