## 1. 产品定位

**一句话：给你硬盘里已有的电子书和漫画，一面可以自己摆的书架。**

Bookrest 是一个本地优先的桌面应用：不导入、不搬动、不接管你的文件，只读取你已有的目录，把散落在各处的电子书与漫画渲染成一面可自由摆放的书架墙。

| 维度 | 说明 |
|---|---|
| 形态 | 桌面应用（Windows 优先，架构上不排除后续其他平台） |
| 数据 | 数据即文件：事实索引与意图文件都是可读的本地文件，无数据库、无云服务 |
| 核心循环 | 添加库 → 后台扫描 → 书架/封面墙浏览 → 拖拽摆放 → 详情查看 → 用默认程序打开 |
| 目标用户 | 藏书散落在多个目录/盘位，用服务器或阅读器管不过来、又不想被某个「库」绑架的人（首要用户：作者本人） |
| 与同类的关系 | 不是电子书服务器、不是阅读器、不是元数据编辑器，只做「视图层」 |

## 2. 设计原则（不可动摇的五条）

1. **源文件只读**：一个字节都不写（v1 不提供任何写源文件的能力）
2. **零导入**：不要求文件符合任何命名或目录规范，就地索引
3. **本地优先**：运行时数据全在本机，NAS 慢不拖累界面
4. **离线可看**：库不可达时用本机镜像渲染，自动降级为只读
5. **不做阅读器**：双击交给系统默认程序，不与阅读器生态争地盘

## 3. 非目标（明确不做）

- 不做阅读、阅读进度、书签与批注
- 不做电子书服务器（OPDS、多用户、远程访问）
- 不做元数据编辑器（不写回文件；v1 也不写书旁旁车文件）
- 不做格式转换、不做资源下载与搜索
- 不做账号体系、云同步、遥测统计
- v1 不支持 CBR（rar），只索引 zip 系（CBZ）与 EPUB/PDF 的基础元数据
- v1 不做自由 2D 画布摆放（先做「架层 + 顺序」）

## 4. 核心场景（用户故事）

| 编号 | 场景 |
|---|---|
| US-1 | 我有 8000 本漫画散在 3 个盘里，想一眼看到全貌，并按系列摆好 |
| US-2 | 移动硬盘没插的时候，我仍然想看看自己的书架长什么样 |
| US-3 | 我想知道哪几个系列缺卷、哪些书重复了、哪些文件损坏了 |
| US-4 | 我把某个系列的文件夹改名或挪了位置，希望摆放不变 |
| US-5 | 我想双击一本书，就用我惯用的阅读器打开它 |

## 5. 功能需求

优先级：P0 = v0.1.0 必须；P1 = v0.2.0；P2 = v0.3.0 或以后。

### FR-1 库与扫描

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-1.1 | 添加库（选择根目录）；支持注册多个库，界面单库视图、可切换 | P0 | 添加后立即可见书架骨架 |
| FR-1.2 | 首次全量扫描在后台执行，界面全程可交互 | P0 | 扫描中可浏览、可拖拽 |
| FR-1.3 | 增量扫描：目录 mtime 剪枝 + 文件 (size, mtime) 比对，只处理变化项 | P0 | 无变化时 2 万本 ≤ 3s |
| FR-1.4 | 扫描可取消、可断点续扫（游标持久化） | P0 | 中途退出后再次启动继续 |
| FR-1.5 | 周期性全量校验（默认每 7 天或每 20 次启动，可配） | P1 | 可覆盖「文件原地覆盖写」盲区 |
| FR-1.6 | 扫描进度与差异以事件流推送界面（新书渐进出现） | P0 | 扫描中书架逐步补齐 |
| FR-1.7 | 扫描并发可配（默认 2–4），网络存储自动降并发 | P0 | 可配置生效 |

### FR-2 书架视图

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-2.1 | 封面墙：网格卡片（封面、标题、系列、卷号） | P0 | 2 万本滚动流畅 |
| FR-2.2 | 书脊视图：架层 + 书脊（封面裁条 + 竖排书名），无封面用稳定色块 | P0 | 无封面不出现空白块 |
| FR-2.3 | 拖拽排序：书架内改顺序、跨书架拖动 | P0 | 拖拽后立即生效并可持久 |
| FR-2.4 | 虚拟滚动：只渲染可见区 | P0 | DOM 节点 ≤ 200 |
| FR-2.5 | 搜索与过滤：关键词（标题/系列/作者）、标签、系列 | P0 | 2 万本过滤 ≤ 200ms |
| FR-2.6 | 书架管理：新建/重命名/删除；智能书架（按规则自动入架） | P1 | 规则改动即时反映 |
| FR-2.7 | 书脊宽度按页数映射；无封面按标题 hash 取色 | P1 | 同书颜色稳定 |

### FR-3 详情页

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-3.1 | 展示本地事实：封面大图、系列/卷号、作者/画师、页数、体积、格式、相对路径、指纹 | P0 | 与文件系统一致 |
| FR-3.2 | 展示在架位置，并支持「在书架上定位」 | P0 | 一键跳转到书架对应位置 |
| FR-3.3 | 可编辑：自定义标题、标签、评分（只写意图，不写文件） | P0 | 源文件不变 |
| FR-3.4 | 外链跳转：AniList / Bangumi / Goodreads / 豆瓣（按标题搜索链接） | P1 | 点击在浏览器打开 |
| FR-3.5 | 操作：用默认程序打开、在文件夹中显示、复制路径/文件名 | P0 | 路径含中文与空格时正常 |

### FR-4 元数据

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-4.1 | 内嵌解析：CBZ 的 ComicInfo.xml、EPUB 的 OPF、PDF 的 XMP 基础字段 | P0 | 有内嵌元数据时优先采用 |
| FR-4.2 | 文件名规则解析（系列/卷号/作者），结果可纠正 | P0 | 常见命名格式可解析 |
| FR-4.3 | 覆盖优先级：用户覆盖 > 内嵌 > 文件名；覆盖只写意图 | P0 | 重扫后覆盖不丢 |
| FR-4.4 | 在线元数据补全 | P2 | v1 明确不做 |

### FR-5 体检报告（只读，不改任何文件）

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-5.1 | 缺卷检测：系列卷号断档清单 | P1 | 断档可定位到系列 |
| FR-5.2 | 重复检测：指纹相同 → 全文件 hash 二次确认 | P1 | 报告只列疑似，不自动删 |
| FR-5.3 | 损坏检测：zip 无法打开、页数异常、封面缺失 | P1 | 与缩略图失败联动 |
| FR-5.4 | 命名混乱清单：给出建议名并导出 CSV（由用户自行执行改名） | P1 | 导出可用 Excel 打开 |

### FR-6 存储与同步

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-6.1 | 本机镜像为运行时数据（事实索引、意图、缩略图缓存） | P0 | 启动不阻塞于库 |
| FR-6.2 | 库内快照 `.bookrest/`：shelf.json 与 index.jsonl 默认开，缩略图默认关 | P0 | 换机只拷 `.bookrest/` 即可恢复摆放 |
| FR-6.3 | 意图变更去抖异步回写（默认 5s），退出前强制 flush | P0 | 断网不影响本地编辑 |
| FR-6.4 | 所有写入原子（临时文件 + rename），保留滚动备份 | P0 | 断电不产生半写文件 |
| FR-6.5 | 冲突处理：库内 rev 更新 → 备份 + 提示，绝不静默覆盖 | P0 | 冲突文件可人工比对 |
| FR-6.6 | 设置项：镜像位置、库内副本开关、索引/缩略图同步开关、去抖时长、扫描并发 | P0 | 改设置即时生效 |
| FR-6.7 | 纯本机模式：关闭库内写入（只读挂载场景的保命开关） | P0 | 库目录零写入 |

### FR-7 离线模式

## 6. 验收指标（可验证）

| 指标 | 目标 | 验证方法 |
|---|---|---|
| 启动到可交互（2 万本库，热态镜像） | ≤ 1.5s | 计时脚本 |
| 增量扫描（无变化，2 万本，本机盘） | ≤ 3s | 计时脚本 |
| 首次全量扫描（2 万本） | 后台 ≤ 5min，界面全程可交互 | 计时 + 手测 |
| 内存占用（2 万本） | ≤ 300MB | 任务管理器 |
| 缩略图缓存体积 | ≤ 6KB/本（2 万本 ≈ 120MB） | 目录统计 |
| 源文件零写入 | 扫描/浏览/编辑后，源文件 mtime 与 hash 不变 | 前后对比脚本 |
| 离线可用性 | 拔盘后书架 100% 可浏览（含封面与摆放） | 手测 |
| 崩溃安全 | 强杀后已确认的意图不丢（仅去抖窗口内的最后一次可丢） | 手测 |
| 单本元数据扫描成本（热） | ≤ 0.5ms/本 | 基准脚本 |

## 7. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 本地藏书生态与影子图书馆相邻 | 分发/收款通道的合规摩擦 | 不内置下载与搜索；README 明确只做本地文件视图 |
| CBR（rar）需外部解压库 | 覆盖面缺口 | v1 明确不支持并写入非目标 |
| 网络存储性能差异大 | 首次扫描慢 | 三段式扫描 + 剪枝 + 低并发 + 可取消 |
| 文件原地覆盖写（目录 mtime 不变） | 漏检变更 | 周期全量校验 + 手动强制重扫 |
| 跨设备冲突 | 摆放丢失 | rev + 备份 + 提示，不做自动合并 |
| 单人维护 | 项目易停摆 | 架构上砍掉一切非必要依赖，v1 范围收紧 |

## 9. 开放问题（评审时拍板）

1. 外壳：Wails v3 beta / Wails v2 / 纯 Go + 本地 HTTP + 浏览器
2. 索引存储：JSONL（推荐）vs SQLite
3. 界面技术：vanilla TS + 轻量库（推荐）vs Svelte / Preact
4. 多库：v1 是否同时支持多库注册（当前写法：注册多个、界面单库）
5. 缩略图缓存是否也写库内（当前默认：关）
